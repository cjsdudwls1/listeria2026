매번 코드를 짜고 돌리기 전에 검수 에이전트에게 코드 검수를 맡긴다(사용자 2026-11-06 "매 코드 짜고 돌리기전 검수 에이전트한테 코드 검수 맞기기 규칙 추가"). 계획서 §8 에도 넣음.

**Why:** 계획서 검수처럼 코드도 실행 전에 독립 검수를 거쳐야 잘못 돌린 실험을 다시 하지 않음.
**How to apply:** 단계(0-1, 1-1 …)마다 코드를 쓰면 실행 전에 프로젝트 맥락 없는 검수 에이전트(코드·계획서 해당 절만 줌)에게 버그·계획 어긋남 검수 → 지적 반영 → 실행, 검수 결과·고친 내용은 실험 로그에. [[feedback-light-review-then-proceed]] 와 같이 검수만 받고 바로 진행(승인 대기 없음). 관련 [[listeria-1102-final-integrated-plan]].

**2026-11-12 다시 확인**: 실행 중 대기열을 바꾸는 작은 수정(최종 고르기 스크립트·설정·중요도 한 줄·MLflow 기록 경로)도 사용자 "ㅇㅇ 항상 검수받도록" → 검수 지적 반영 뒤 내가 새로 쓴 코드도 실행 전 다시 검수 에이전트(1개, effort 낮게)에 맡김.
