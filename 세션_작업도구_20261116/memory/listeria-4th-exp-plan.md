계획 파일: `리스테리아ML2/exp/다음실험_계획_4차.md` (제목 '교수님 2번 실험 계획'; '정함' / '미결'). 실행은 사용자가 '시작'할 때. 우선순위 4(일정은 [[listeria-experiments-schedule-1026]]).

정함(2026-10-26 사용자):
- 식품 속성 = DB `ba_data.t_aw_cl` 값만, 품목 분류표 기준 고정표(③), 기간 없음, DB 조회일 기록. 구현 정의(분류표 받기·하위 범위 등)는 미결.
- train 행당 h 1개 유지(서버 공용이라 60개 안 함) → 복제 누수·메모리 문제 해소.
- 제품명 변수 사용 가능, 대신 다듬기: 묶음 안에서 실제 쓰인 컬럼만 남기고 컬럼별 중요도 확인(TF-IDF 500개 중 110개만 쓰임 등), 다른 묶음도 같은 방식.
- ~~시료 단위로 센 과거 이력·WOE 등은 행 기준 재계산~~ → 10-26 저녁 취소(사용자 "그대로 둬": 운영 때도 같은 DB 값으로 만들 수 있어 운영엔 상관없음). 이력·WOE·제품명 과거 유형 모두 시료 기준, k 3차대로.
- 제품명(10-26 저녁): 그날 제품명은 운영 때 검사 제품명을 미리 안다는 전제, 제품명 유형(뭉치) 정의는 fold train 기간 자료로만, TF-IDF 컬럼 선별은 낱말 기준.
- 내 2번은 10-26 저녁 '이 계획 − 제품명'으로 했다가 같은 날 밤 '내 1번 결과 모델 + 튜닝·불균형 처리'로 바뀜(이 계획과 분리).
- ~~조기 종료도 구간 가중 PR-AUC~~ → 10-27 취소(사용자 "4차도 현행 유지하자"): 고르기 = 구간 가중, 조기 종료 = 평균 PR-AUC 로 3차·내 1번·내 2번과 같음. 중간점검 보고서 7절의 '지표 통일은 그 뒤 실험에서' 문장과 어긋남(보고서 수정은 10-27 중지 상태).
- 이력 변수 시점: train 행 T−1 까지 매일, validation·test 는 train 끝 값 1년 고정, 운영은 재학습 때 DB 최신 기준 재계산.
- 딥러닝은 VAE·Transformer 적용 LSTM 만, 앙상블 없음. window 80일 고정, WOE 등 다 넣고 변수 선택(씨앗 3개), 고위험 품목 모델 접음, 1등 모델 튜닝 고도화·불균형 처리.
- **10-27 교수님 통화·카톡으로 모델 비교 설계 바뀜**(위 '딥러닝 2개만·앙상블 없음' 대체, 기준 = 내 2번 CatBoost + 제품명): [[listeria-1027-professor-call]].
- 기준 = 3차 최종(test 0.0785). 보고 = 표 두 개(Recall 0.80 고정 비교 / 교차검증 기준선 운영 성능) + 상위 k% 무작위 대비 배수.

**Why:** 3차 점검에서 드러난 문제를 고치고, 교수님 1번 보고서 7절 한계를 극복하는 모습을 다음 보고서에 보이려고.
**How to apply:** 새 결정은 계획 파일 '정함'으로 옮겨 적고 미결은 사용자에게 설명 후 정함. 관련 [[listeria-1020-professor-call]], [[listeria-report-structure-1022]].
