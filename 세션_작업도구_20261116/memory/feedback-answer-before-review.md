사용자가 질문하면 그 답을 먼저 바로 내고, 사용자가 변동사항을 말할 기회를 준 뒤에 반영하고 검수를 맡긴다. 순서 = 답 → 사용자 회신(변동사항) → 반영 → 검수.

**Why:** 2026-11-06 계획서 41차 때 사용자가 '이동평균 차감 30 근거'·'2022-06-30 근거'를 물었는데, 답을 내기 전에(같은 응답 안에서 반영 에이전트를 먼저 띄우고) 반영과 42차 검수 4개를 돌림 → 사용자 "너가 내 질문에 대답을 빨리 쳐 해야 내가 변동사항있으면 말해주고 너가 반영을해서 검수를 맡기지. 검수 먼저했다가 변동사항있으면 어쩌려고". 답에 따라 계획이 바뀔 수 있어 먼저 돌린 검수는 버려짐(검수 3개 중단).

**How to apply:** 사용자 질문이 들어온 응답에서는 도구 호출보다 답을 먼저 쓰고, 답이 결정에 영향을 줄 수 있으면(근거 질문·대안이 있는 것) 반영·검수를 띄우지 말고 사용자 회신을 기다린다. 이미 돌고 있는 검수가 있으면 답과 함께 "변동사항 있으면 말해 달라"고 하고, 변동이 오면 그 검수는 멈춘다. [[feedback-explain-first-work-on-order]] 와 같은 뿌리.
