2026-10-20 사용자가 식품 도메인 전문가에게 확인: 검사 결과는 **분기마다 한꺼번에 DB에 올라온다** → "90일 빼고 하라"(고정 90일, 사용자 결정).

- 뜻: 운영 때 T 직전 결과는 DB에 없으므로, 과거 검사 결과로 만드는 입력 칸(과거 검출 이력 `e2hist.py` 등)은 학습·시험 때도 결과 날짜 ≤ T−90 만 쓰게 맞춤. 운영 모델의 학습 행은 빼지 않음(사용자 이해: "이미 학습된 모델로 예측").
- 이전 상태: 3차 사양 `리스테리아ML2/exp/3_시간순교차검증/사양_20261020.md` 31줄 "과거 이력 칸·외부 지표 등은 지금처럼 T 전날까지", `cv.py` 머리말도 T 전날까지 — 10-20 기준 아직 안 바꿈.
- 비교: 아플라톡신 `toxin_2026/01_아플라톡신/train/experiments/history_risk/history.py` = `의뢰일 + lag_days(30) < D`, 결과 통보일 칼럼 없어 보수적 30일(의뢰-제조 간격 중앙 8일·95% 77일), 학습 행은 안 뺌. 기본 파이프라인 분할은 제조일 기준, horizon_curve 는 경계 60일 엠바고(기상 창 겹침 이유).
- 적용 범위(WOE·제품명 과거 유형 N1·교차검증 학습 범위까지인지)는 사용자 확인 필요.
- **바뀜(10-20 저녁 사양 확정, 10-26 코드 대조로 확인):** 3차 최종 사양 1절·8절은 '결과 시차를 반영하지 않는다'로 정함. 3차 코드도 반영 안 함(train 행 = T 전날까지, validation·test 행 = fold train 끝 값 고정). 90일 판 코드는 `백업_20261020_1850_시차판_고치기전_src` 에만 있음. 교수님 2번 계획 1-8 도 T−1 유지. 그러니 "3차가 T−90 결정을 빠뜨렸다"고 말하면 틀림.
