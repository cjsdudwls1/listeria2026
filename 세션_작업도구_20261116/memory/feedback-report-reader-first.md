2026-10-22 사용자가 3차 연구 보고서 초안(35쪽)을 직접 읽고 지적("읽는 사람 입장에서", "지금 분량이 상상 이상으로 많아서 당황스러움. 구성은 괜찮은데 좀 지엽적", "묶음 중요도는 또 뭐임 복잡한거 많이 썻네 귀찮게", 제품명 '○ 모델:' 부분 "개 씹 최악").

**Why:** 보고서 독자는 우리 작업 맥락을 모른다. 내가 작업 중 만든 말(묶음·섞기 중요도·단위)과 설명 꼬리표, 세부 예외는 읽기만 어렵게 한다.

**How to apply:**
- 내부 용어를 만들지 말 것. 여러 칸으로 된 변수는 처음 한 번 "칸 전체를 하나의 변수로 다룸"이라 하고 이후 '변수'. 중요도는 처음에 permutation importance(Breiman, 2001)와 scikit-learn 의 '내장 중요도 치우침' 경고를 근거로 짧게 소개하고, 이후 'permutation importance'로만.
- '왜:' '어떻게:' 꼬리표 대신 이유가 문장에 녹아 편안히 읽히게. 방법마다 근거 1~2줄은 유지.
- 표는 한 칸에 칼럼 이름 등을 쉼표로 몰아넣지 말고 줄·칸을 나눠 표 선으로 구분. 칼럼 나열은 글 대신 표.
- 처음 나오는 기호·약어(T, h, HACCP, SPI3·SPI6 등)는 그 자리에서 짧게 풀이. 근거 자료는 괄호로 출처 데이터 파일명.
- 결론에 필요 없는 세부는 빼고 짧게 — 사용자는 본문 절반 판도 요청함. 이해 안 되는 그림(로그 근거 산점도 등)은 넣지 말 것.
- 사용자가 '보고서에 반영하지 말라'고 한 사항(중요도 0 변수 이야기)은 쓰지 않는다.

**10-22 저녁 추가 지적(절반 판 검토, 매우 강하게)**: "학습 자료, 시험 기간 이딴 말 쓰지 말고 train, test 이렇게 알아듣게 써", "칸 이름이 아니라 컬럼명 아님? 일반적으로 알아듣는 말 좀 써라 … 한국말 안 쓰면 암살당하니?", "창 이란 단어도 쓰지 마", "나무갈림이 뭔 소리임? 억지 번역 제발 그만", "뺌·더함 말고 제외·삭제·추가", "괄호로 (4.1) 이런 식으로 붙이는 거 읽는 사람 입장에서 아무짝에 쓸모없음".
- 억지 번역 금지 → 현업에서 쓰는 말: train / test / validation(맞혀 보는 X 금지), fold(겹 금지), window(창 금지), 컬럼·컬럼명(칸·칼럼 금지), 트리·분할(split)(나무·갈림 금지), 하이퍼파라미터(설정값), threshold(판정 기준값), 로그 스케일(눈금), 시퀀스(순서열), seed(씨앗), 셔플(섞음).
- 변수·자료를 덜어 냄 = 제외/삭제, 넣음 = 추가. 표 결정 값 '뺌/되돌림' → '제외/유지'.
- 절·장 번호 참조('(4.1)', '(Ⅱ부 3.1)', '6장에서') 쓰지 말 것 — 표·그림 참조 '(아래 표[n] 참고)'는 양식이라 둠.
- 표 머리글 '만드는 법' → '설명'. 이해 안 되는 표(품목 검사 건수 구간 표)는 그림으로.
