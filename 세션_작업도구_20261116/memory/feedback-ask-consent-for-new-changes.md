작업 도중 사용자가 아직 모르는 새로운 결정사항·수정사항이 생기면 임의로 정해서 진행하지 않는다. 중간중간 사용자에게 묻고 동의를 받은 뒤 진행한다.

**Why:** 2026-10-12 사용자가 같은 턴에 두 번 말함 — "내가 모르는 새로운 결정사항이 생기면 너 임의로 하지말고 나한테 중간중간 물어보셈", "모든 작업 중간중간 내가 모르는 새로운 수정사항이 생기면 나한테 동의 구하면서 작업해". 조인 규칙·데이터 처리처럼 결과에 책임이 따르는 일을 사용자가 직접 정하려 한다([[feedback-raw-data-no-preprocessing]], [[feedback-no-rerun-without-asking]] 와 같은 맥락).

**How to apply:** 사용자가 이미 정한 것(지시문에 적힌 것)은 다시 묻지 않고 진행한다. 지시에 없던 선택(코드에 없던 부분을 새로 짜야 함, 남의 코드를 고쳐야 함, 파일 삭제·이동 방식, 패키지 설치, 규칙 해석이 갈리는 곳)이 나오면 AskUserQuestion 으로 선택지와 내 추천을 같이 내고 답을 받는다. 답과 무관한 작업은 그동안 계속한다. (내 해석: 사소한 구현 세부까지 다 묻는 것이 아니라 결과·파일·남의 코드에 영향이 있는 선택이 대상.)

**2026-10-20 세 번째 지적([종합] 세션)**: "아니 잠깐만 멋대로 하지말고 같이 결정을 하고해". 내가 다른 세션들의 결정 요청에 사용자 대신 답하고(AE 점수 수정 승인, 실험 추가 실행 승인, 표 구성 승인), 사용자 지시를 넓게 해석해 새 설정을 정해 전달함(기준 변경 때 Optuna 목적 함수를 다목적으로 바꿔 보냄). → 지휘하는 동안에도 세션들이 묻는 결정·설정 선택은 사용자에게 가져가 함께 정한 뒤 전달. 사용자 지시를 그대로 옮기는 것만 바로 하고, 해석이 들어가는 것(목적 함수·모델 목록·추가 실행·삭제 범위 등)은 먼저 묻기. 확실한 계산 오류 수정도 '고칠까요?'로 확인.
