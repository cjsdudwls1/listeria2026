**미해결 확인 항목 (2026-09-17 사용자 지시).** 품목제조대장 조인에서 시료표 품목제조번호의 숫자 아닌 글자('-', '호' 등)를 지우고 이어 붙여 대장 `prdlst_report_no` 와 맞춘 방식(예: `20110476011-5` → `201104760115`, `19950262006-289호` → `19950262006289`)이 식품안전정보원 내부 번호 체계인지 모름. 식정원 내부 관계자에게 검증받아야 함. 영향: `ledg_match_type`='숫자만 일치' 570행(고유 번호 250개)의 ledg_* 컬럼 전부. 현재 근거는 제품명 대조(같거나 포함 93.7%)뿐이며 기관 확인이 아님.

**Why:** 사용자가 "니가 식정원 방식인지 모르잖아"라고 지적함. 연구용 데이터셋 설명에 확인 안 된 변환을 쓰면 안 됨.

**How to apply:**
- **평소 대화에서는 꺼내지 않는다.** 사용자가 연구용·최종 데이터셋을 확정하겠다고 하거나 ledg_*(품목제조대장) 컬럼을 넣기로 확정하려 할 때, 확정 전에 이 검증이 안 됐다고 한 번 알린다.
- 사용자가 검증했다고 말하면(누가·언제·결과) 작업기록.md '확정 전 필수 확인' 절에 결과를 적고 이 메모리를 지우며 MEMORY.md 줄도 뺀다. 부정 답변이면 570행 연결을 빼거나 규칙을 바꿀지 사용자에게 결정을 받는다.
- 2026-09-28 노트북 6-2(pog_daycnt 조인)에서 사용자는 "원문 일치만"을 골라 숫자만 변환을 쓰지 않았다(선택지에 '변환이 식정원 체계인지 미확인'을 적어 알림). 숫자만 변환을 다시 쓰려 할 때 이 항목을 알린다.
