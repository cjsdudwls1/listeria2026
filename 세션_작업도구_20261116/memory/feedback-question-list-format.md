질문 리스트(워드)는 모델링 의사결정(타겟 범위, 데이터 한계·DB 활용, 제거할 데이터)의 근거를 **다른 사람의 공식 의견**으로 남기기 위한 문서다.
- 작성자가 정규식 등으로 임의 확인한 내용은 "데이터로 확인됨"이라 쓰지 않는다. "이러이러한 작업을 임의로 해 본 결과 ~하다. 그래서 ~인 것 같은데 맞는가?" 형태로 모두 질문한다.
- 근거 형식: ① 어떤 DB·테이블·값을 어떤 키로 어떻게 조인했는지(담당자가 읽으며 맞는지 판단할 수 있게) → ② 무슨 작업을 어떻게 했는지 + 결과 DataFrame 캡처 → ③ 그래서 이런 상황(추정) → ④ 이런 의문.
- 개조식, 핵심만 간단 명료하게.
- **구분을 최소화** (2026-09-14 v0.1 검수 지적: "구분이 너무 많음. 표도 많고 하위 행도 많고… 처음 보는 입장에서 하나도 안 읽힘"). 질문 1건 = 1쪽: 한 줄 제목 → 질문 상자(데이터 담당자 1줄·도메인 전문가 1줄) → 근거 네 문장(데이터·작업·결과·그래서(추정)) + 표 1개(행 3~6개). 소제목·하위 글머리표·질문 하위 번호 없이, SQL·세부 규칙은 부록으로.

**Why:** 사용자는 돈을 받고 하는 용역이라, 전문가 공식 의견 없이 모델러가 판단하면 나중에 책임 문제가 생긴다고 강조했다 (2026-09-14). "니가 도메인 전문가보다 똑똑해도 공식 의견 없이는 큰일남."

**How to apply:** 질문·보고 문서에서 해석은 항상 "추정 — 확인 필요"로 표시하고 질문으로 끝낸다. 수치는 원자료 그대로 집계한 것만 쓰고 가공은 하지 않는다 ([[feedback-raw-data-no-preprocessing]]). 예시본: `리스테리아ML/docs/질문리스트/리스테리아_질문리스트_예시3건_v0.1.docx`, 생성기 `리스테리아ML/scripts/make_question_docx.py` ([[listeria-question-list-doc]]).
