2026-09-15 사용자가 리스테리아 DB수집 결과보고 엑셀(v2)을 행 단위로 지적함.
- 처음 보는 사람(교수님)이 한 번에 이해해야 함: "출처 r15" 같은 내부 행번호 약어 금지 → "데이터출처 엑셀 빨간 글자: 데이터명"처럼 풀어 씀. "부분·대체" 같은 모호한 판정어 금지 → "일부만 있음 / 대체 값 / 사용 여부 결정 필요"처럼 뜻이 보이는 말.
- "관측소별 센서 차이" 같은 추정을 근거 없이 쓰지 말 것: "니가 어떻게 아냐"를 대비해 판단 방법(예: 그 항목 0건인데 같은 관측소 기온은 99.8% 기록)을 같이 적음.
- 결측은 컬럼별로 왜 비었는지 분해해서 적음(행 없음 / 그 항목 미기록 관측소 / 그날만 빈 값).
- 0값을 빼고 조인했다면 "굉장히 큰 실수" → 값 있음 기준에 0 포함 여부를 명시.
- 문자보고 시트에 "한글명(컬럼명)" 병기를 요청했다가 같은 날 취소함 → 문자보고는 한글명만, 영문 컬럼명은 상세 시트에.
- 방법론(최근접 관측소 선정 등)은 단계별로 구체적으로, 공간 단위는 예시값과 함께("필지 단위(주소 예시)").
- DB 값을 한국어로 옮겨 쓸 때는 어느 표·칼럼의 원래 값인지 같이 적음. 2026-09-15 "지오코딩 정밀도 '낮음'"이라고만 썼더니 "니가 만든거임? 아님 데이터 테이블에 있는 칼럼임?"이라고 물음 → `geocode_status` 원값 'low_precision'처럼 표기하고, 칼럼 설명이 없으면 없다고 밝힘.

**Why:** 식정원 관계자·교수님이 물으면 답하고 책임질 수 있어야 함([[feedback-raw-data-no-preprocessing]]와 같은 맥락).
**How to apply:** 보고·질문 문서를 쓸 때 약어·모호어를 풀고, 각 수치 옆에 산출 기준과 판단 근거를 붙임. 관련: [[listeria-nb3-db-join-findings]], [[feedback-question-list-format]].
