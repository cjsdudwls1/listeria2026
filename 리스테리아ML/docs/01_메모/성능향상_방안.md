# 리스테리아 검출 예측 — 성능 향상 방안 (2026-09-29)

실험 1(`EXP/1`, MLflow 실험 `리스테리아_EXP1`)의 베이스라인 결과를 보고, 데이터·도메인(리서치팀 예측인자 PPT, `리서치팀문서/위해요소별_중요인자_데이터출처.xlsx` 빨간 글자, `docs/01_메모/info.md`)을 함께 고려해 정리한 방안이다.
근거 수치는 `scripts/probe_feature_candidates.py`(탐색용, MLflow 기록 없음, 약 3분) 로 다시 낼 수 있다.

### 왜 낮은가 — 데이터에서 확인한 것

1. **모델이 좌표를 외운다.** 기본값 LightGBM 이득의 65%가 `lat`, 35%가 `lon`. 좌표·`legal_dong_code` 를 빼고 정규화하면 test roc_auc 0.734 → 0.830(정규화 설정끼리 비교).
2. **가장 센 신호(업소 이력)를 안 쓰고 있다.** 같은 `addr` 에서 기준일 30일 이전에 검출된 적이 있으면 test 검출률 2.49%, 없으면 0.12%(약 20배). 주소별 과거 검출 비율(평활)만으로 test roc_auc 0.833 · pr_auc 0.060 — 현재 최고 모델(0.019)의 3배.
3. **검출의 73%가 품목코드로 구분되지 않는 두 코드에 있다.** `train_prdlst_code` Z3800000000000 '기타기준규격외' 791건(40%)과 Z2700000000000 '정액,수정란,종란' 640건(33%). 후자는 `prdlst_code` Z2700400000000 한 값이며 제품명이 '수출용 팽이버섯', 'ENOKI MUSHROOM', '권지실 바닥 표면' 등이라 실제로는 팽이버섯·재배장 환경검체다. 정보는 `prduct_nm`(제품명)에만 있는데 실험 1에서 삭제했다.
4. **제품명 키워드가 검출률을 크게 가른다.** 팽이 5.72%(284건), 육회 3.50%, 연어 3.02%, 회 1.62%, 한우 1.19%, 포장육 1.05% ↔ 우유·아이스크림·빵·굴·상추·토마토 0건. info.md 10번("가열 여부 × 그대로 섭취")과 맞다.
5. **검출의 82%가 검사목적 '기타'(업체 자체 의뢰).** `ba_data.m_org_lims_data_info.inspct_purps_code` = IM02000007 이 검출 1,645/2,052(DB 전체), 수거검사(IM02000003) 101, 수입검사(IM02000001) 98. test 도 241/287. 이 칼럼은 아직 모델에 없다.
6. **시기 드리프트.** 2020년 검출률 0.60%(다른 해 0.13~0.36%) — 검사기관 O000084 의 팽이버섯 수출검사 287건. 월별 패턴도 train(12월 최고) ↔ test(7~10월 최고)가 반대라 val 에서 고른 임계값이 test 에서 안 맞는다.
7. **행이 독립이 아니다.** 검출 1,969건 중 974건이 같은 주소·같은 날 묶음 안에 있고, test 검출 287건은 188묶음이다(`result_value` 의 '양성,양성,양성,양성,양성' = n=5 검체).
8. **기상은 하루값 1,700칼럼이 특정 하루를 외운다.** XGBoost `soil_t30_d084` 한 칼럼 29.9%. 기상만 베이스라인은 무작위 수준.
9. **식품 aw·pH·염도는 검출 행에서 덜 붙는다.** 값 있는 비율 51/40/41% ↔ 검출 행 27/14/15%. "비어 있음" 자체가 품목 표지가 된다.
10. **검사 결과는 의뢰 후 중앙값 9일, 95% 20일, 99% 37일 뒤에 나온다**(`inspct_compt_de − reqest_de`). 이력 피처를 만들 때 이 지연을 넣어야 누수가 없다.

## 1. 데이터 정제 (`EXP/1/1_데이터정제.ipynb` 입력 기준)

1. **예측 범위·라벨을 먼저 정한다 — 환경검체·공정시료·수출 팽이버섯·정도관리(QC) 시료를 분리**(제외 / 층 변수 / 별도 모델 중 택1). 근거: 진단 3·6, 4.ipynb 의 기관 주소·QC 시료. 점검에서는 제외해도 성능이 비슷(범위 축소 + I 설정 test 0.903 / 0.039). 결정은 사용자·전문가 몫(질문리스트 A 항목).
2. **Z2700400000000 → '정액,수정란,종란' 라벨 오류를 모델팀에 확인·정정.** 근거: 제품명 전부 팽이버섯·재배장 검체(질문리스트에 이미 있음).
3. **같은 주소·같은 날 묶음을 평가 단위로 쓴다.** 임계값 선택·신뢰구간은 묶음 부트스트랩, 필요하면 묶음 단위로 집계한 데이터셋도 병행. 근거: 진단 7.
4. **예측 시점을 의뢰일로 통일한다.** 이력·검사목적 피처는 `reqest_de`(m_org, 100% 채움) 기준으로 "그 시점에 알 수 있는 것"만 계산. 기상은 제조일이 있는 행에만 붙인다. 근거: `mnfctur_de` 에 제조일·의뢰일·선적일 세 사건이 섞여 있음(2.ipynb 4절).
5. **시기 가중치.** 2020 팽이버섯 사건 행을 낮게 가중하거나 연도별 가중, 최종 모델은 train+val 로 재학습. 근거: 진단 6.
6. **좌표·법정동 원값을 빼고 시도/시군구 수준 + 이력 피처로 바꾼다.** 근거: 진단 1.
7. **m_org 원자료를 정식으로 다시 받는다**(`data/collected/raw/raw_m_org_lims_data_info_listeria.parquet`, SELECT *). 지금 `collected/probe/` 파일은 탐색용 14칼럼이다.

## 2. 만들면 좋은 변수

1. **업소 이력**(`addr`·`mnfctur_cmpny_nm`·영업신고번호 단위): 과거 검사 건수, 검출 건수, 검출 비율(베이지안 평활), 마지막 검출 후 경과일, 최근 1년 검출 여부. **기준일 − 30일 이전 행만** 집계. 근거: 진단 2·10.
2. **품목·검사기관·품목×업소 이력** 같은 방식. train 에 없는 코드도 자연스럽게 처리된다(진단: `prdlst_code` 는 test 에 train 에 없는 코드 66종).
3. **제품명(`prduct_nm`) 피처.** 1단계 키워드 플래그: 팽이·버섯·연어·회/횟감·필렛·초밥·육회·포장육·원료육·정육·냉동·냉장·훈제·햄·소시지·치즈 / 환경검체(바닥·표면·배수구·공정·설비·권지) / 가열전·세척전 / 수출 / 우유·아이스크림(살균군). 2단계: 문자 n-gram TF-IDF + 로지스틱의 out-of-fold 확률을 피처로. 근거: 진단 3·4.
4. **식품유형 룩업(전문가 확인 필요): 가열·살균 여부 × 그대로 섭취(RTE) × 보존온도(냉장/냉동/실온).** 출처 후보: 식품공전 유형(`ba_data.t_prdlst_cl` lv3 이하), 2.ipynb 6-4 초안, 품목제조대장 `prsrv_distb_stdr_cn`(보존유통기준)·`mnf_cnd_cn`(제조조건)의 냉장/냉동/실온/살균 키워드, LIMS 시료상태 코드 IM11(9.6%만 채움), 제품명 키워드. 근거: info.md 9~12번, PPT '식품 유형·저장 및 유통 온도·포장 유형'.
5. **LIMS 코드**: 검사목적(IM02), 검사종류(IM03), 의뢰시스템(CI07), 운반방법(IM08), 시료상태(IM11). 근거: 진단 5, 점검 I. **판정형식코드(IM15)는 넣지 않는다**(누수 의심, test 이득 없음).
6. **월·계절은 품목군·기관과의 교호로만.** 월 단독은 무작위 수준(진단 6). 국내 원물에서만 계절 신호 기대(info.md 13).
7. **기상은 창 집계로**: D-1~7·14·30·100 평균·최고·최저, 강수 합, 생육 범위 일수(PPT 한계 −2~45℃, 최적 30~37℃ → 예: 최저기온 ≥ −2℃ 일수, 평균 ≥ 30℃ 일수), 토양온도·토양수분 같은 방식. 전체 행에 붙이되 "국내 원물·최소가공 × 제조일 기준" 플래그를 함께 두어 모델이 교호를 배우게 한다(info.md 13 은 원물에만 의미가 있다고 보지만, 사용자 원칙 2026-09-29 "일단 다 넣고 필요 없으면 뺀다"). 근거: 진단 8.
8. **식품 내재 요인(aw·pH·염도)**: 결측 표시 변수를 두고, 값은 상위 품목 계층(lv2/lv3) 대표값 또는 리서치팀 문헌값으로 보완(결측 채움이라 사용자 승인 필요). 근거: 진단 9, PPT 우선순위 1·3·4위.
9. **수입 행**: 제조국(`s_org_lims_data_info.mnf_nation_cd`), 수입화주, 해외제조업소 이력, 선적→의뢰 일수(중앙값 17일).
10. **업소 특성**(`ba_data.t_bsn_lcns_ledg`): 업종코드, HACCP 지정(`t_prdlst_mnf_ledg.haccp_appn_no`), 불량식품관리업소 여부(`futyfoodmanagebssh_yn`), 중점관리업소(`emphsmanagebssh_yn`), 종업원 수·면적. 영업신고번호 채움 27% — 정의서 뜻 확인 필요.
11. **최적·한계 범위 변수(예측인자 PPT 표, 사용자 제안 2026-09-29).** 인자마다 PPT 의 최적·한계 값을 그대로 기준으로 쓴다 — 기온 최적 30~37℃·한계 −2~45℃, 토양온도 8~15 / 8~30℃, 토양 pH 6.5~7.0 / 5.0~8.0, 수분활성도 0.97 / 0.90~0.997, 식품 pH 7.0 / 4.0~9.6, 염도 한계 ≤16%. 인자별로 (a) 한계 안 여부, (b) 최적 안 여부, (c) 최적까지 거리(한계 폭으로 나눈 값), (d) 기상 창(7·30·100일) 안에서 한계 안 일수·최적 안 일수·한계 밖 일수. 값은 aw·pH·염도(`t_aw_cl`), 기온·토양온도(기상 조인), 토양 pH(수집 후)에서 온다. 근거: PPT 우선순위 표, 카디널 성장 모델의 정의(최소·최적·최대) 자체가 이 값이다.
    - 만드는 법: 인자 x 마다 `x_in_limit` = (한계 하한 ≤ x ≤ 한계 상한), `x_in_opt` = (최적 하한 ≤ x ≤ 최적 상한), `x_dist_opt` = |x − 최적 중앙| ÷ (한계 상한 − 한계 하한). 염도는 한계 상한만 있으므로 `na_in_limit` = (염도 ≤ 16) 과 `na_ratio` = 염도 ÷ 16. 기상 창(7·30·100일)은 `temp_days_in_limit`·`temp_days_in_opt`·`temp_days_out`(토양온도도 같은 이름 규칙). 인자 값이 없으면 NaN 그대로.
    - 지금 값이 있는 비율: 기온·토양온도 100%(국내), aw 51.0%, pH 39.5%, 염도 40.9%, 토양 pH 0%(수집 전).
    - 문헌 카디널 식(Silva 2020·Rosshaug 2012 의 Tmin·Topt·Tmax 로 만드는 γ 값)은 수식 엑셀 쪽이라 `리스테리아_성장식_피처화_구상.md` 2-1·3절에 둔다.
12. **문헌 성장식 피처** — `리서치팀문서/리스테리아 식.xlsx` 의 µmax·생장확률·검출확률 식을 전 행에 계산해 넣는다. 구상은 `docs/04_실험계획/리스테리아_성장식_피처화_구상.md`.

## 5. 불균형 처리

1. **재표집 없이 정규화 + 조기종료(val average_precision) + 임계값 이동**을 기본으로. 근거: 점검에서 `scale_pos_weight=30` 을 넣자 1회 반복에서 멈추고 test roc 0.693 으로 나빠짐.
2. **`scale_pos_weight`·CatBoost `auto_class_weights` 는 튜닝 후보** {1, 5, 18(√비율), 50}. 순위 지표엔 영향이 작고 확률 눈금만 바뀌므로 임계값과 함께 본다.
3. **음성 언더샘플링 + 배깅**(BalancedBagging/EasyEnsemble, 양성 전부 유지, 음성 1:20~1:50): 학습 속도·안정성, pr_auc 소폭 개선 기대.
4. **SMOTE 계열은 비권장.** 범주형·고카디널리티·텍스트 입력과 같은 업소 묶음 구조에서 가짜 행을 만든다. 굳이 쓰면 SMOTE-NC 로 수치 부분만.
5. **focal loss**(LightGBM/XGBoost 사용자 정의 목적함수) — 선택.
6. **평가는 pr_auc + recall 목표(30·50%)에서 precision·예측양성 수**, 묶음 부트스트랩 신뢰구간, 검사목적·국내외·품목군별 분리 지표. accuracy 는 보지 않는다.

## 6. 모델·학습 절차

1. **정규화 하이퍼파라미터** (num_leaves 15~31, min_child_samples 200 이상, learning_rate 0.03, colsample 0.7, `cat_smooth` 큰 값) + val 조기종료 → Optuna(`.env` `AFLA_OPTUNA_DIR`).
2. **튜닝은 train 안 시간순 교차검증**(확장 창, 연 단위 fold, fold 양성 수 확인)으로, val 은 조기종료·임계값에만.
3. **앙상블**: XGBoost·LightGBM·CatBoost + 업소 이력 점수의 순위 평균.
4. **최종 모델은 train+val 재학습 후 test 1회.**
5. 국내/해외·원물/가공은 모델을 나누기보다 층 변수로 두고 **층별 성능을 따로 보고**(해외 train 양성 77건).
6. LSTM 은 기상 창 집계에서 신호가 확인된 뒤에만.

## 7. 권장 순서

1. EXP/2: m_org raw 수집 → 이력 피처 + 제품명 키워드 + LIMS 코드 + 좌표 제거 + 정규화·조기종료 (예상 test pr_auc 0.019 → 0.04 안팎).
2. 범위 결정(환경검체·수출 팽이버섯) + 묶음 단위 평가.
3. 식품유형 룩업(가열·RTE·보존온도) + 품목제조대장·인허가대장 조인.
4. 다른 위해요소 이력 + 회수·행정처분.
5. 기상 창 집계 + 최적·한계 범위 변수 + 문헌 성장식 피처(별도 문서) + 빨간 글자 미확보분 수집.
6. 튜닝·앙상블·불균형 기법 비교.
