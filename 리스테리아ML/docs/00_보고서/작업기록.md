### 조인 방법 (코드에서 확인한 사실)
1. 시료 파일(`data/listeria_body.parquet`)에는 품목제조번호가 없음 → 시료 고유키 `lims_data_key` 로 DB 전처리 시료표 `ready_data.hazard_preprocessed_data` 를 1:1로 붙여 `prdlst_mnfctur_sttemnt_no`(데이터셋 열 `db_prdlst_mnfctur_sttemnt_no`)를 가져옴
2. 그 번호 원문이 대장 `ba_data.t_prdlst_mnf_ledg.prdlst_report_no`(품목 보고 번호)에 있으면 원문으로 연결(`ledg_match_type`='원문 일치')
3. 원문이 대장에 없을 때만, 숫자가 아닌 글자를 모두 지운 숫자열로 다시 찾음(`'숫자만 일치'`). 예: `20110476011-5` → `201104760115`, `19950262006-289호` → `19950262006289`
4. 대장에 같은 번호가 여러 행이면 1행만 고름: ① 삭제 안 된 행(`del_yn`≠'Y') ② 최종 수정 일시(`last_updt_dtm`) 최신 ③ 품목 보고 대장 번호(`prdlst_report_ledg_no`, 전부 16자리라 글자 순서 = 숫자 크기) 큰 행 ④ 세 기준이 모두 같으면 추출 파일에서 앞에 있는 행. 삭제 안 된 행이 없으면 삭제 행이 붙음
5. 고른 대장 행의 8개 열 값을 그대로 붙임(값 변환·채움 없음)

3. **붙은 대장 행이 같은 제품인지** (시료 파일 `prduct_nm` 제품명 ↔ 대장 `prdlst_nm`; 소문자화·기호/공백 제거 후 비교)

4. **품목코드 대조**: 대장 `prdlst_cd` ≠ 시료 `prdlst_code` 29,176행(14.3%). 상위는 코드 체계 차이(예: 시료 C0202050200000 가열양념육 ↔ 대장 C0316050100000, 시료 C0318090100000 유가공품류 ↔ 대장 C0318090300000). 불일치 행도 제품명 유사도 0.3 이상 96.5%(일치 행 98.1%) → 대부분 같은 제품의 코드 표기 차이

   - 대장 번호(`prdlst_report_ledg_no`)까지 같은 행: 6개 번호 12행. 그중 수정 일시까지 같은 번호 2개(시료 2행)는 파일 순서로 결정됨. `[냉동]참치마요 유부초밥`(20210363114191)은 두 행의 유통기한이 '제조일로부터 9개월'/'6개월'로 달라 어느 값이 붙을지 추출 순서에 달림

   - 현재 규칙이 고른 행보다 제품명이 더 맞는 다른 행이 있는 시료 33행(번호 20개, 검출 0, 그중 유통기한 값이 달라지는 19행). 번호 재사용으로 보이는 예: 번호 2013044800111 — 시료 '경옥고이순주수제요거트'(기준일 2019-11-12)에 2021-11-23 보고된 '이순주 밤여乳 MILK' 행이 붙음, 이름이 맞는 행은 삭제된 2019-10-29 보고 행

### 판단
- 연결 키(`prdlst_report_no`)와 '원문 → 숫자만' 순서는 근거가 있고, 코드는 컬럼사전 설명대로 동작함
- 다만 보고서에는 (a) 번호가 시료표(`ready_data.hazard_preprocessed_data`)에서 온다는 점, (b) '기호'가 아니라 숫자 아닌 글자 전부를 지운다는 점, (c) 완전 동점이면 파일 순서라는 점, (d) 값이 시료 당시가 아니라 2026-09-14 대장 상태라는 점, (e) 빈 값의 두 이유를 함께 적어야 함 — 현재 컬럼사전 '연결 방법' 문구에는 (a)(c)(d)(e)가 없음(컬럼사전 수정은 사용자 확인 후)
