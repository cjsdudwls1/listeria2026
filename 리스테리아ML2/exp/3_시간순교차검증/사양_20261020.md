# 3차 실험 계획 — 시간순 교차검증 (2026-10-20 개정, [종합] 세션)

이 파일만 따른다. 옛 본문(F2·다목적 튜닝·모델 5개 등)은 지웠다. **아직 검수 중 — 사용자가 '계획 확정'이라고 하기 전에는 실행하지 않는다.**
근거: 교수님 통화(10-20 오전: 홀드아웃·교차검증·리핏, 10-20 저녁: 결과 시차·이력 값 고정·튜닝 1개·범주 변수)·교수님 카톡(10-18 h 구간 가중·방식 B·트랜스포머·셔플, 10-20 리핏 설명)·사용자 결정(10-20).

## 0. 날짜 말
- T = 예측하는 날, h = 며칠 뒤를 맞히는지(1~60), d = 맞히려는 날(시료 기준일 mnfctur_de) = T + h.
- 예: T = 2025-07-01, h = 60 → d = 2025-08-30.

## 1. 데이터 나누기
- **시험(홀드아웃)** = T ∈ 2025-07-01 ~ 2026-05-01 인 행(모든 h 같은 305일; 2026-05-01 = 자료 끝 2026-06-30 − 60일). 무엇을 고르는 데도 쓰지 않고 맨 끝에 한 번만 채점.
- **교차검증 3겹** = 학습 구간을 늘려 가며 다음 1년을 맞혀 봄(교수님 "6년 하고 1년, 7년 하고 1년, 8년 하고 1년 이렇게 세 번 정도만" — 실제 자료 시작이 2015-04 라 약 7·8·9년):

| 겹 | 학습 행(정답 날 d) | 맞혀 보는 행(예측하는 날 T) |
|---|---|---|
| 1 | 자료 시작(2015-04) ~ 2022-06-30 | 2022-07-01 ~ 2023-05-01 |
| 2 | ~ 2023-06-30 | 2023-07-01 ~ 2024-05-01 |
| 3 | ~ 2024-06-30 | 2024-07-01 ~ 2025-05-01 |
| 최종(리핏) | ~ 2025-06-30 | 시험 2025-07-01 ~ 2026-05-01 |

- **결과 시차는 학습 범위에 반영하지 않는다**: 검사 결과는 분기마다 늦게 DB 에 반영된다(도메인 전문가). 교수님(10-20 저녁)은 "반영할 수가 없지", "안 해도 내가 보기엔 상관이 없지", 운영은 학습 때 만든 값을 1년 동안 그대로 쓰고 1년마다 다시 학습하는 방식이라고 함 → 학습 끝은 앞당기지 않고, 이력 칸은 2절처럼 학습 끝 값으로 고정한다(사용자 확정).
- **예측일 05-02 ~ 06-30 을 채점하지 않는 이유**: 시험 자료는 2026-06-30 에서 끝나 60일 뒤 정답이 있는 마지막 예측일이 05-01 이다(예측일 05-20 이면 h=1 정답 05-21 은 있고 h=60 정답 07-19 는 없음). 모든 h 를 같은 305일(07-01 ~ 05-01)로 채점해 h 끼리 공평하게 비교하려고 이렇게 자르고, 겹도 시험과 같은 규칙을 쓴다(10-19 사용자 결정 '(가)'). 채점만 빼는 것이고 시료는 버리지 않는다 — 정답 날이 학습 끝 안인 겹에서는 학습에 쓴다.
- 실제 배포 모델은 그 시점까지 나온 자료로 학습하고 정해진 주기(예: 1년)마다 다시 학습한다 — 보고 때 갱신 주기를 적는다(9절).

## 2. 입력 칸
- 기상: T−L ~ T−1(L = 창 길이).
- **과거 검사 결과로 만드는 칸**(과거 이력: 품목군 3단계·시군구·단위 × 5년·1년 스무딩 검출률, log(1+검사 수), 1년 불확실성 / WOE 4개: 시도·시군구·2단계·3단계 / 제품명 과거 유형 N1: 뭉치 비율·뭉치 스무딩 검출률):
  - 학습 행: 그 행의 예측일 T 전날까지의 시료로 센다(굴러가는 창, 직전 1년·5년).
  - 맞혀 보는 행·시험 행: **그 겹(최종) 학습 끝 날까지의 시료로 만든 값(학습 끝 날 기준 직전 1년·5년)을 그 해 내내 그대로 쓴다(학습 끝 값 고정)**. 교수님이 설명한 운영 방식(학습 때 만든 품목별·지역별 검출률을 1년 동안 그대로 쓰고 1년마다 다시 학습)과 같은 조건(사용자 확정, 10-20 저녁).
- **스무딩 계수 k**: 후보 10·30·50·100·200(교수님 `Listeria/1차 고도화 전략/readme.md` 4.1절과 같음) 중 교차검증 고르기 점수(3절)로 고름(튜닝 전, `run3.py kselect`). 고르는 모델·입력·창 = 바닐라 ② 1위(1차 베이스라인) + 과거 이력 핵심 칸(사용자 확정 — 창과 같은 규칙). 2차 값 k=10 은 옛 검증 해(= 겹 3 맞혀 보는 해)로 고른 것이라 쓰지 않음. 전국 검출률 p0 는 같은 창으로 다시 계산(지금 방식).
- **그날 제품명 칸**(N2 그날 뭉치 유형·N0 낱말 빈도)은 튜닝의 '변수 전부'에 처음부터 넣는다 — 운영 때 그날 검사할 제품명을 입력한다는 전제(보고 때 명시). N0 낱말 사전은 겹마다 그 겹 학습 기간으로 만든다.
- **제품명 뭉치 21개 정의**는 2024-06-30 까지 검출 수로 고른 것이다. 겹 학습 기간만으로 다시 세면 겹 1(≤2022-06-30)에서 2개(버섯류_팽이외 검출 3·업소 2, 비가열식육_생햄 검출 2·업소 2)가 선정 기준(검출 ≥5·업소 ≥3)에 못 미치고, 겹 2·3·최종은 21개 모두 넘는다([질문] 세션 점검, `data/중간/제품명/겹별_선정기준_점검/`). **사용자 결정: 칸은 그대로 두고 한계로 적는다.**
- 외부 지표(친환경·지하수·HACCP)·토양·표준강수지수는 지금처럼 사용가능일 기준.
- 이상치 점수(AE·VAE): 겹마다 그 겹 학습 행의 불검출만으로 다시 학습(학습 행 점수는 그 행을 안 본 모델로). 입력의 이력 칸도 위 규칙을 따른다.

## 3. 점수
- **고르기 점수**(모델·창·k·튜닝·변수) = 교차검증 세 겹 평균 **구간 가중 PR-AUC** = 0.5 × 평균(H1~20) + 0.3 × 평균(H21~40) + 0.2 × 평균(H41~60)(h 마다 PR-AUC). 교수님 10-18 카톡 "단기 예측이 더 중요하다고 가정하고 구간별 가중치로 모델 비교", 가중치는 2차와 같음(사용자 확정).
- **판정 기준값** = 60개 h 를 합친 예측에서 Recall ≥ 0.80 인 기준값 가운데 Precision 최대. 겹 점수는 그 겹 맞혀 보는 행으로, 시험용은 세 겹 맞혀 보는 행 예측을 합친 것에서 같은 규칙으로 정해 최종 모델의 시험 예측에 그대로 쓴다(교차검증에서 정한 값을 고정해 리핏 모델에 쓰는 순서).
- **보고 지표**(그 기준값에서 h 마다 → h 평균): Accuracy·Precision·Recall·F1·ROC-AUC·PR-AUC, TP·FN·FP·TN·N(h 당 평균 건수), 검사축소율 = 1 − (TP+FP+FN)/N, 상위 1·5·10·20% 포착률, 그리고 구간 가중 PR-AUC·구간 가중 Recall(같은 가중치)을 같이 적는다. 점수만 적는다(표준편차·신뢰구간 말 없음).

## 4. 순서
1. **틀·점검**: 교차검증 3겹 + 시험 채점 코드, 겹별 행 수·검출 수. 이 개정판 반영 뒤 다시 점검.
2. **바닐라 ① (창 100일)**: XGBoost·LightGBM·CatBoost(각각 기상 요약·일별 원값) + BiLSTM. 기본 설정값 그대로(조기 종료만, 지금 코드). 입력 = 범주 4(시도·시군구·2단계·3단계) + h + 기상.
3. **바닐라 ②**: ①의 1위 (모델, 입력)으로 창 10~100일(10일 단위) → 1차 베이스라인.
4. **k 고르기**: ② 1위 (모델, 입력, 창) + 과거 이력 핵심 칸으로 후보 5개를 고르기 점수로 비교(2절).
5. **튜닝**: **바닐라 ② 1위 모델 하나만** Optuna 30회(교수님 10-20 저녁 "바닐라로 쫙 돌린 다음에… 제일 좋은 모델을 찾아. 그리고 그걸로 튜닝해서 돌려봐", 사용자 확정). 목표 = 고르기 점수(구간 가중 PR-AUC) 하나, 변수 전부(그날 제품명 칸 포함), 창 = ②에서 고른 창.
6. **후보 고르기(사람)**: 상위 후보를 구간 가중 PR-AUC·60일 평균 PR-AUC·Recall 0.8 에서의 Precision·FP·FN 표로 [종합]에 보냄 → 사용자가 고름. 교차검증 결과만 본다.
7. **변수 빼기**(교수님 순서): 고른 설정값을 복사(get_params → set_params)해 묶음 중요도가 낮은 묶음부터 빼고 교차검증 → 고르기 점수가 오르면 뺀 채로, 아니면 되돌림 → 한 회차에서 뺀 것이 없을 때까지. **묶음 중요도 = 묶음 섞기**(사용자 확정): 겹마다 맞혀 보는 행에서 그 묶음의 칸을 통째로 행끼리 섞었을 때 고르기 점수(구간 가중 PR-AUC)가 떨어진 양 → 세 겹 평균. 회차마다 그때 기준 모델로 다시 잰다. **범주 4칸(시도·시군구·2단계·3단계)과 h 는 빼기 후보에서 제외**(교수님 10-20 저녁 "카테고리 변수… 그건 걸러낼 수가 없어요"). 자동 조합 탐색은 하지 않는다(사용자 확정).
8. **최종(리핏)**: 같은 설정값·변수로 학습 행 전체(d ≤ 2025-06-30) 재학습, 부스팅 반복 수 = 세 겹 최적 반복 수 평균, BiLSTM 은 에폭 수 = 세 겹 최고 에폭 수 평균(run3.py:650) → 시험 1년 한 번 채점.
9. **고위험 품목**: 학습 행 검출 비중 상위 5개 품목(3단계)만으로 같은 틀(교차검증 → 시험). 겹마다 그 겹 학습 행으로 다시 고르고, 최종은 학습 행 전체로 고름. 같은 품목에서 전체 모델과 비교.
10. **이상치 탐지 단독**: 학습 행 불검출만으로 학습 → 겹별 맞혀 보는 행의 검출을 얼마나 잡나 → 시험.
11. **딥러닝 단계**: 트리 작업 뒤 따로. 모델 목록은 사용자와 정함.
12. **표**: 석민쌤 성능비교표(노로바이러스추가)·다현쌤 구글 시트는 새 결과로 채움. 보고서는 사용자 지시 때 한 번에.

## 5. 지키는 것
- 시험 1년은 8단계 전에는 보지 않는다(코드: 고르는 단계에서 시험 행을 만들면 오류로 멈춤).
- 나누기는 시간순만(무작위 나누기 안 씀).
- 학습 행 순서: 트리는 행 순서와 상관없이 학습하고, BiLSTM 은 에폭마다 무작위로 섞는다(dl3.py) — 교수님 10-18 '계절 섞어 학습'은 이미 충족.
- 변수 빼기 판단은 교차검증으로만(시험으로 판단하지 않음).
- 랜덤 포레스트·로지스틱은 3차에서 뺀다(로지스틱은 2차에서 실험함).

## 7. 알고 있는 한계(보고 때 적음)
- 조기 종료를 겹의 맞혀 보는 행으로 해서 교차검증 점수가 실제보다 조금 높게 나온다. 진짜 점수는 시험 1년.
- 운영 때 그날 검사 제품명을 입력하는지는 확인되지 않았다.
- 이력 칸은 학습 행에서는 직전까지 자료로, 맞혀 보는 행·시험 행에서는 학습 끝 값으로 고정해 쓴다. 그래서 그 해 뒤쪽 예측일수록 오래된 값을 쓴다(운영과 같은 조건, 1년마다 다시 학습 전제).
- 제품명 뭉치 정의에 겹 1 뒤 기간 검출이 섞임(2절: 겹 1 에서 2개 뭉치가 그 겹 기간만으로는 선정 기준 미달) — 겹 1 점수에서 제품명 칸이 조금 좋게 나올 수 있음. 겹 2·3·시험은 해당 없음.

## 8. 실험 세션이 고칠 것(계획 확정 뒤에만 전달)
- 겹 학습 끝 = 맞혀 보는 해 시작 전날(2022-06-30·2023-06-30·2024-06-30), 최종 2025-06-30 — 90일 앞당김 없음(시차 반영 전 판 `백업_20261020_1605_시차반영전/` 과 같음).
- 과거 이력·WOE·N1: 학습 행 = 예측일 전날까지 굴러가는 창, 맞혀 보는 행·시험 행 = 그 겹(최종) 학습 끝 날 기준 값 고정. T − 90일 창은 쓰지 않음(이미 고친 시차 코드를 이 규칙으로 바꿈).
- 고르기 점수 = 구간 가중 PR-AUC(0.5·0.3·0.2) — 바닐라·창·k·튜닝 목표·변수 빼기 판단·묶음 섞기 중요도 모두.
- 튜닝 = 바닐라 ② 1위 하나만(Optuna 30회).
- 변수 빼기 = 묶음 섞기 중요도, 범주 4칸·h 는 빼기 후보 제외(이미 고친 코드와 같음).
- kselect = 바닐라 ② 1위 (모델, 입력) + hist_core(이미 고친 코드와 같음).
- 뭉치 한계 문구(cv.py limitations) = 겹 1 미달 2개(버섯류_팽이외·비가열식육_생햄)만. 칸은 빼지 않음.
- cfg3.py·cv.py 설명 문구의 옛 내용 정리, 자체 점검 다시.
- 바닐라부터 다시 실행(학습 범위가 바뀌어 지금까지 낸 교차검증 점수는 비교에 쓰지 않음). **실행은 [종합]이 '계획 확정'을 보낸 뒤에만.**

## 9. 보고 때 적을 것
- 모델 갱신 주기(예: 1년마다 다시 학습)와 이유: 검사 결과가 분기마다 늦게 반영되고, 이력 값은 학습 끝 값으로 고정해 쓴다(교수님 10-20 저녁).
- 입력 변수를 표준 형식 표로 기록 — 나중에 누가 와도 보고 갱신할 수 있게(교수님 10-20 저녁).
